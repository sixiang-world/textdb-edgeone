# TextDB EdgeOne v1.3.0 — 实施计划

> **配套设计规格：** `docs/superpowers/specs/2026-09-04-v1.3.0-design.md`
> **Goal:** 实现 4 个功能：本地 Key 浏览、写入队列/重试、Markdown 增强、OpenAPI 文档
> **Architecture:** 4 个 Phase 按风险从低到高推进，每个 Phase 独立可验证。全部为前端改动，Edge Function 不变。
> **Tech Stack:** React 19 + TypeScript + Tailwind v4 + shadcn/ui + idb + react-markdown 插件 + swagger-ui-react

## Phase 3：写入队列/重试（改动写入路径，重点测试）

### Task 3.1：writeQueue 工具库

- [ ] `npm install idb`（+ `@types`？idb 自带类型）
- [ ] 创建 `src/lib/writeQueue.ts`
- [ ] 定义 `QueueItem` 接口和 `QueueStatus` 类型
- [ ] 用 `idb.openDB('textdb', 1)` 创建数据库，upgrade 时建 `write-queue` store（keyPath: id）+ status index
- [ ] 实现 `enqueue(item)`：生成 uuid（`crypto.randomUUID()`），status=pending，写入 DB，触发 `processQueue()`
- [ ] 实现 `processQueue()`：串行取 pending 项，调用对应 API（writeData/deleteData/uploadFile）
- [ ] 成功：status=done，从 DB 删除，触发成功回调（toast + recordKey + onStatsRefresh）
- [ ] 失败：retryCount++，指数退避（1s/2s/4s），setTimeout 重试；超 3 次 status=error，存 lastError
- [ ] 实现 `retryItem(id)`：status 改回 pending，触发处理
- [ ] 实现 `discardItem(id)`：从 DB 删除
- [ ] 实现 `initQueue()`：页面加载时扫描 pending/processing 项重新处理；监听 `online` 事件
- [ ] 实现订阅机制：队列变化时通知 UI（用简单的 EventEmitter 或 React context）
- [ ] IndexedDB 不可用时降级为直接调用 API（现有行为）

### Task 3.2：QueueStatus 组件

- [ ] 创建 `src/components/QueueStatus.tsx`
- [ ] 订阅 writeQueue 的状态变化（pending 数、error 数、error 列表）
- [ ] 浮动指示器（右下角）：pending > 0 显示旋转图标+数字；error > 0 显示红色徽章+数字
- [ ] 点击展开面板：队列列表（key、type 图标、status、retryCount、lastError）
- [ ] error 项："重试"按钮 → retryItem；"丢弃"按钮 → discardItem
- [ ] 底部"全部重试"按钮
- [ ] 队列为空时隐藏指示器

### Task 3.3：集成到 WriteCard

- [ ] handleWrite：改为 `enqueue({type:'write', key, value, password, newPassword})`，不直接 fetch
- [ ] handleDelete：改为 `enqueue({type:'delete', key, password})`
- [ ] 写入/删除的成功 toast 移到 writeQueue 的成功回调中
- [ ] 保留 loading 状态？队列是异步的，按钮点击后立即恢复（不再有 loadingOp）。可以加"已加入队列"的短暂反馈
- [ ] recordKey 移到 writeQueue 成功回调中（确保只记录成功写入的 key）

### Task 3.4：集成到 FolderUpload

- [ ] 批量上传：逐个 `enqueue({type:'upload', ...})`，不再 await 逐个上传
- [ ] 进度显示改为队列 pending 数（或保留现有进度，从队列状态取）

### Task 3.5：集成到 App

- [ ] `App.tsx` useEffect 中调用 `initQueue()`
- [ ] 渲染 `<QueueStatus />`（全局浮动）
- [ ] onStatsRefresh 回调传入 writeQueue（写入成功后刷新统计）

### Task 3.6：验证（重点）

- [ ] `npm run lint` + `npm run typecheck` 通过
- [ ] 正常网络：写入 → 队列 pending → processing → done，toast 成功，key 出现在历史
- [ ] Chrome DevTools 设 Offline：写入 → 入队 → 失败 → 自动重试（1s/2s/4s）→ 超 3 次 error
- [ ] Offline 下写入后刷新页面 → 队列项保留 → 恢复网络 → 自动处理成功
- [ ] error 项点"重试" → 重新发送
- [ ] error 项点"丢弃" → 从队列移除
- [ ] 同一 key 连续写入 3 次 → 串行执行，最终值是第 3 次（无竞态）
- [ ] IndexedDB 不可用（隐私模式） → 降级为直接 fetch，不报错
- [ ] 删除带密码的 key → 队列项含密码 → 验证通过后删除

## 风险与回退

| 风险 | 影响 | 回退方案 |
|---|---|---|
| swagger-ui-react 体积大（~100KB） | 首屏加载变慢 | 改为 React.lazy 动态导入 ApiDocs 页 |
| idb 在某些浏览器不支持 | 队列功能不可用 | 已设计降级为直接 fetch |
| Markdown 插件冲突 | 渲染异常 | 逐个插件启用，二分定位 |
| 写入队列改变交互习惯 | 用户困惑 | 保留 toast 反馈，队列指示器清晰 |
| IndexedDB 存密码明文 | 共享电脑风险 | 文档注明，后续 E2EE 时处理 |
