# TextDB EdgeOne v1.3.0 — 设计规格

> 版本：v1.3.0（进行中）
> 日期：2026-09-04
> 范围：4 个功能 — 本地 Key 浏览、写入队列/重试、Markdown 增强、OpenAPI 文档

## Background

v1.2.0 完成了前端重构（Sidebar 布局）、密码保护、AI 爬虫识别。v1.3.0 聚焦**使用体验闭环**和**开发者体验**：

- 用户写入 key 后没有本地记录，刷新后找不到自己写过什么
- 弱网环境下写入失败直接丢数据，没有重试机制
- Markdown 渲染只有基础 GFM，缺少代码高亮、目录、公式、图表
- API 文档是手写的静态页面，没有标准 spec，无法导入 Postman 或在线调试

本版本不改变存储模型、不引入用户系统、不做 TTL/CDN/Webhook（见 ROADMAP.md）。

## Design Goals

1. **零服务端改动** — 4 个功能全部在前端完成（OpenAPI spec 是静态文件），Edge Function 逻辑不变
2. **渐进增强** — 新功能不破坏现有交互，localStorage/IndexedDB 不可用时静默降级
3. **体积可控** — Markdown 插件中 Mermaid/KaTeX 动态加载，主 bundle 增量 < 50KB gzip
4. **可观测** — 写入队列状态对用户可见（pending/error 指示器），失败可手动干预

## Tech Stack

- React 19 + TypeScript + Tailwind v4 + shadcn/ui（现有）
- `idb` — IndexedDB 轻量封装（新增，~1KB gzip）
- `rehype-highlight` + `highlight.js` — 代码高亮（新增）
- `rehype-slug` + `rehype-autolink-headings` — 标题锚点（新增）
- `remark-math` + `rehype-katex` — 数学公式（新增，动态加载）
- `remark-mermaid` — Mermaid 图表（新增，动态加载）
- `swagger-ui-react` — OpenAPI 渲染（新增）

## 功能 1：本地 Key 浏览（localStorage）

### 数据模型

```ts
interface KeyRecord {
  key: string;
  createdAt: number;      // 首次写入时间（epoch ms）
  lastWrittenAt: number;  // 最近一次写入时间
  size?: number;          // 最近一次 value 的字节数（可选）
}
```

- localStorage key：`textdb-key-history`
- 存储格式：JSON array，按 `lastWrittenAt` 降序
- 上限：200 条，超出淘汰最旧（FIFO by lastWrittenAt）
- 只存元数据，不存 value（避免 localStorage 容量压力和隐私问题）

### API 封装 `src/lib/keyHistory.ts`

| 函数 | 说明 |
|---|---|
| `listKeys(): KeyRecord[]` | 读取全部历史，按时间降序 |
| `recordKey(key: string, size?: number): void` | 写入成功后调用；已存在则更新 lastWrittenAt |
| `removeKey(key: string): void` | 删除成功后调用 |
| `clearHistory(): void` | 清空本地记录（不影响服务端数据） |
| `searchKeys(query: string): KeyRecord[]` | 按 key 子串过滤 |

所有操作包 try/catch，localStorage 不可用时静默返回空。

### UI 组件 `src/components/KeyHistory.tsx`

- 可折叠面板，默认收起，标题显示"最近写入 (N)"
- 展开后：搜索框 + 列表 + 底部"清空本地记录"
- 列表项：key（等宽字体，可点击复制）、相对时间（`x 分钟前`）、大小（如有）
- 每行操作：点击 → 回调 `onSelect(key)`（父组件填入输入框并触发读取）；删除图标 → 回调 `onDelete(key)`
- 空状态："还没有写入记录"

### 集成点

| 文件 | 改动 |
|---|---|
| `src/components/WriteCard.tsx` | 写入成功 → `recordKey`；删除成功 → `removeKey`；接收 `onSelect` 回调填 key |
| `src/components/FolderUpload.tsx` | 每个文件上传成功 → `recordKey` |
| `src/components/pages/OperatePage.tsx` | 在 WriteCard 上方渲染 KeyHistory，传入 onSelect/onDelete |
| `src/lib/keyHistory.ts` | **新增** |
| `src/components/KeyHistory.tsx` | **新增** |

### 边界情况

- 隐私模式 localStorage 不可用 → KeyHistory 不渲染（检测 `typeof localStorage !== 'undefined'` + try/catch）
- 多标签页同步 → 监听 `window.addEventListener('storage')`，跨标签页更新时刷新列表（可选，v1 可先不做）
- key 正则 `[0-9a-zA-Z_]`，无 XSS 风险

## 功能 2：写入队列/重试（IndexedDB）

### 数据模型

```ts
type QueueStatus = 'pending' | 'processing' | 'done' | 'error';

interface QueueItem {
  id: string;              // crypto.randomUUID()
  type: 'write' | 'delete' | 'upload';
  key: string;
  value?: string;          // write / upload 时有
  password?: string;
  newPassword?: string;
  status: QueueStatus;
  retryCount: number;
  lastError?: string;
  createdAt: number;
  updatedAt: number;
}
```

- IndexedDB database：`textdb`（version 1）
- Object store：`write-queue`，keyPath: `id`
- Index：`status`（用于按状态查询）

### 队列处理器 `src/lib/writeQueue.ts`

基于 `idb` 库封装。核心逻辑：

1. **入队** `enqueue(item)` — 生成 id，status=pending，写入 IndexedDB，触发处理
2. **处理** `processQueue()` — 串行取出 pending 项（一次一个，避免 KV 并发写冲突）
3. **发送** — 调用现有 `writeData` / `deleteData` / `uploadFile`
4. **成功** — status=done，24 小时后自动清理（或立即删除，v1 立即删除）
5. **失败** — retryCount++，指数退避（1s → 2s → 4s），最多 3 次；超过则 status=error
6. **恢复** — 页面加载时扫描 pending/processing 项，重新入处理流程
7. **手动操作** — `retryItem(id)` / `discardItem(id)`

### UI 组件 `src/components/QueueStatus.tsx`

- 全局浮动指示器（右下角或顶部工具栏）：
  - pending > 0：旋转图标 + 数字
  - error > 0：红色徽章 + 数字
  - 全部 done：隐藏
- 点击展开队列详情面板：
  - 每项：key、type 图标、status、retryCount、lastError（如有）
  - error 项："重试" / "丢弃" 按钮
  - 底部"全部重试"按钮

### 集成点

| 文件 | 改动 |
|---|---|
| `src/lib/writeQueue.ts` | **新增** — IndexedDB + 队列处理器 |
| `src/components/QueueStatus.tsx` | **新增** — 队列状态指示器 |
| `src/components/WriteCard.tsx` | handleWrite/handleDelete → `enqueue` 替代直接 fetch；成功 toast 由队列回调触发 |
| `src/components/FolderUpload.tsx` | 批量上传 → 逐个 `enqueue` |
| `src/App.tsx` | 挂载时 `initQueue()`，渲染 QueueStatus |
| `package.json` | 新增 `idb` 依赖 |

### 关键决策

- **透明替换**：用户点击"写入"后立即看到"已加入队列"，不阻塞 UI；成功/失败通过 toast 通知
- **与功能 1 联动**：队列处理成功后才 `recordKey`，避免记录从未成功的 key
- **密码存储**：队列项含 password 明文，存本地 IndexedDB。风险等同于前端 state（共享电脑需注意），v1 接受；后续 E2EE 时一并处理
- **串行处理**：同一 key 的多次写入按顺序执行，避免竞态

### 边界情况

- IndexedDB 不可用 → 降级为直接 fetch（现有行为），不显示队列指示器
- 页面关闭时 pending 项保留，下次打开自动重试
- 网络恢复时自动触发处理（监听 `online` 事件）

## 功能 3：Markdown 增强

### 现有基础

`src/components/MdRenderer.tsx` 已用 `react-markdown@10` + `remark-gfm@4`，是独立路由 `/md/{key}`。

### 插件方案

| 插件 | 功能 | 加载方式 | 体积(gzip) |
|---|---|---|---|
| `rehype-highlight` + `highlight.js` | 代码语法高亮 | 主 bundle | ~30KB |
| `rehype-slug` | 标题 id 锚点 | 主 bundle | ~1KB |
| `rehype-autolink-headings` | 标题可点击链接 | 主 bundle | ~2KB |
| `remark-math` + `rehype-katex` | LaTeX 公式 | 动态 import | ~40KB |
| `remark-mermaid` | Mermaid 图表 | 动态 import | ~150KB |

### 动态加载策略

```
页面加载 → 拉取 markdown → 检测内容：
  ├─ 含 $...$ 或 $$...$$ → 动态 import remark-math + rehype-katex → 渲染
  ├─ 含 ```mermaid 代码块 → 动态 import remark-mermaid → 渲染
  └─ 普通内容 → 直接渲染（仅核心插件）
```

避免每个 `/md/{key}` 页面都加载 190KB 额外 JS。

### 目录（TOC）

- `rehype-slug` 给 h1-h6 加 id
- 右侧悬浮目录组件，从渲染后的 DOM 提取标题（或用 `rehype-extract-toc`）
- v1：静态目录列表，点击跳转；滚动高亮放到后续优化
- 窄屏（< 1024px）隐藏目录，避免遮挡内容

### 代码高亮主题

- `highlight.js` 的 `github` 主题（light）+ `github-dark`（dark）
- 配合 `next-themes`（已装）切换
- 代码块右上角加"复制"按钮（现有组件模式）

### 集成点

| 文件 | 改动 |
|---|---|
| `src/components/MdRenderer.tsx` | 插件配置、TOC 组件、动态加载逻辑、复制按钮 |
| `src/index.css` | 导入 highlight.js 主题、KaTeX 样式 |
| `package.json` | 新增 6 个依赖 |

### 边界情况

- Mermaid 图表需要客户端渲染，SSR/无 JS 环境不显示（本项目是 SPA，可接受）
- KaTeX 公式渲染失败时显示原始 LaTeX 源码（error 回调）
- 大 markdown 文件（> 500KB）渲染可能卡顿，v1 不做虚拟滚动

## 功能 4：OpenAPI / Swagger 文档

### Spec 文件

`public/openapi.json` — OpenAPI 3.0.3，构建时复制到 dist，可通过 `/openapi.json` 直接访问。

覆盖端点：

| Method | Path | 说明 |
|---|---|---|
| POST | `/update/` | 写入/更新/删除（JSON 或 form-urlencoded） |
| POST | `/{key}` | 直接写入（body=内容，X-Password header） |
| GET | `/{key}` | 原始读取（text/plain） |
| GET | `/p/{key}` | HTML 渲染 |
| GET | `/file/{ext}/{key}` | 按扩展名读取（auto Content-Type） |
| GET | `/md/{key}` | Markdown 渲染（SPA 路由） |
| GET | `/stats` | 统计数据 |
| DELETE | `/{key}` | 删除（X-Password header） |
| OPTIONS | `/*` | CORS preflight |

每个端点含：参数说明（key/value/password/new_password/X-Password）、请求示例、响应示例、错误码。

### 前端渲染

用 `swagger-ui-react` 替换现有 `ApiDocs.tsx`：
- `server` 配置为 `location.origin`（Try it out 发请求到当前域名）
- CORS 已配置 `X-Password` header，Try it out 可正常工作
- 支持"授权"按钮输入密码（swagger-ui 的 authorize 功能，或直接在参数里填）

### 集成点

| 文件 | 改动 |
|---|---|
| `public/openapi.json` | **新增** — OpenAPI 3.0 spec |
| `src/components/ApiDocs.tsx` | 重写为 SwaggerUI 渲染 |
| `src/index.css` | 导入 swagger-ui 样式（或用 swagger-ui-react 自带） |
| `package.json` | 新增 `swagger-ui-react` |

### 边界情况

- swagger-ui-react 体积 ~100KB gzip，仅在 API 文档页加载（React Router 按页拆分，本项目是 SPA 单页，需确认是否 code split。当前 App.tsx 是 switch 渲染，没有 lazy import。v1 可直接引入，后续优化 code split）
- Try it out 的 POST 请求会真实写入 KV，需在文档页提示"这会真实操作数据"

## 跨功能考虑

### 实施顺序（按风险从低到高）

1. **Phase 1：OpenAPI 文档** — 纯新增，零风险
2. **Phase 2：本地 Key 浏览** — 纯前端增量，不影响写入逻辑
3. **Phase 3：写入队列/重试** — 改动写入路径，需仔细测试
4. **Phase 4：Markdown 增强** — 依赖多，体积评估

每个 Phase 完成后跑 `npm run lint` + `npm run typecheck` + 手动验证。

### 验证策略

- 无测试框架（AGENTS.md 确认），验证靠 lint + typecheck + 手动
- 写入队列需模拟弱网（Chrome DevTools offline/throttle）验证重试
- Markdown 需准备测试用例（含代码块、表格、公式、Mermaid）
- OpenAPI 需用 Try it out 实测每个端点

### 不做的事（本版本明确排除）

见 ROADMAP.md "暂不考虑"章节：TTL、SDK/CLI、CDN 缓存、用户系统、AI 摘要、Webhook、版本历史、E2EE、KV 分片、结构化查询。
