# TextDB EdgeOne v1.3.0 — 设计规格

> 版本：v1.3.0（已完成并发布）
> 日期：2026-09-04
> 范围：4 个功能 — OpenAPI 文档、本地 Key 浏览、写入队列/重试、Markdown 增强
> 状态：全部实现，lint + typecheck 通过，已打 tag v1.3.0

## Background

v1.2.0 完成了前端重构（Sidebar 布局）、密码保护。v1.3.0 聚焦**使用体验闭环**和**开发者体验**：

- 用户写入 key 后没有本地记录，刷新后找不到自己写过什么
- 弱网环境下写入失败直接丢数据，没有重试机制
- Markdown 渲染只有基础 GFM，缺少代码高亮、目录、公式、图表
- API 文档是手写的静态页面，没有标准 spec，无法导入 Postman 或在线调试

本版本不改变存储模型、不引入用户系统、不做 TTL/CDN/Webhook（见 ROADMAP.md）。

## Design Goals

1. **零服务端改动** — 4 个功能全部在前端完成（OpenAPI spec 是静态文件），Edge Function 逻辑不变
2. **渐进增强** — 新功能不破坏现有交互，localStorage/IndexedDB 不可用时静默降级
3. **体积可控** — Markdown 插件中 Mermaid/KaTeX 动态加载，主 bundle 增量 < 50KB gzip
4. **可观测** — 写入队列状态对用户可见（pending/error 指示器），失败可手动干预

## Tech Stack

- React 19 + TypeScript + Tailwind v4 + shadcn/ui（现有）
- `idb` — IndexedDB 轻量封装（新增，~1KB gzip）
- `rehype-highlight` + `highlight.js` — 代码高亮（新增，atom-one-dark 主题）
- `rehype-slug` + `rehype-autolink-headings` — 标题锚点（新增）
- `remark-math` + `rehype-katex` — 数学公式（新增，动态加载）
- `mermaid` — Mermaid 图表（新增，动态 import，未使用 remark-mermaid 插件）
- `swagger-ui-react` — OpenAPI 渲染（新增）

覆盖端点（8 个）：

| Method | Path | 说明 |
|---|---|---|
| POST | `/update/` | 写入/更新/删除（JSON 或 form-urlencoded） |

## 功能 2：本地 Key 浏览（localStorage）

### 数据模型

```ts
interface KeyRecord {
  key: string;
  createdAt: number;      // 首次写入时间（epoch ms）
  lastWrittenAt: number;  // 最近一次写入时间
  size?: number;          // 最近一次 value 的字节数（可选）
}
```

- localStorage key：`textdb-key-history`
- 存储格式：JSON array，按 `lastWrittenAt` 降序
- 上限：200 条，超出淘汰最旧（FIFO by lastWrittenAt）
- 只存元数据，不存 value（避免 localStorage 容量压力和隐私问题）

### API 封装 `src/lib/keyHistory.ts`

| 函数 | 说明 |
|---|---|
| `listKeys(): KeyRecord[]` | 读取全部历史，按时间降序 |
| `recordKey(key: string, size?: number): void` | 写入成功后调用；已存在则更新 lastWrittenAt |
| `removeKey(key: string): void` | 删除成功后调用 |
| `clearHistory(): void` | 清空本地记录（不影响服务端数据） |
| `searchKeys(query: string): KeyRecord[]` | 按 key 子串过滤 |

所有操作包 try/catch，localStorage 不可用时静默返回空。

### UI 组件 `src/components/KeyHistory.tsx`

- 可折叠面板，默认收起，标题显示"最近写入 (N)"
- 展开后：搜索框 + 列表 + 底部"清空本地记录"
- 列表项：key（等宽字体，可点击）、相对时间、大小（如有）
- 点击 key → 填入 WriteCard 输入框并触发读取
- 导出 `HISTORY_REFRESH_EVENT = "textdb:history-refresh"` 常量，供 App.tsx 队列成功后 dispatch 刷新
- 空状态："还没有写入记录"

### 集成点

| 文件 | 改动 |
|---|---|
| `src/components/WriteCard.tsx` | 接收 `selectedKey` prop；队列成功后由 App 全局回调 recordKey |
| `src/components/FolderUpload.tsx` | 队列成功后由 App 全局回调 recordKey |
| `src/components/pages/OperatePage.tsx` | 在 WriteCard **下方**渲染 KeyHistory（用户要求从上方移到下方） |
| `src/App.tsx` | 队列 onSuccess 中 dispatch HISTORY_REFRESH_EVENT |
| `src/lib/keyHistory.ts` | **新增** |
| `src/components/KeyHistory.tsx` | **新增** |

### 边界情况

- 隐私模式 localStorage 不可用 → KeyHistory 不渲染（try/catch 检测）
- key 正则 `[0-9a-zA-Z_]`，无 XSS 风险

## 功能 3：写入队列/重试（IndexedDB）

### 数据模型

```ts
type QueueItemStatus = "pending" | "processing" | "error";

interface QueueItem {
  id: string;              // crypto.randomUUID()
  type: "write" | "delete" | "upload";
  key: string;
  value?: string;          // write 时有
  password?: string;
  newPassword?: string;
  fileName?: string;       // upload 专用
  fileRelativePath?: string;
  fileContent?: string;
  fileSize?: number;
  status: QueueItemStatus;
  retryCount: number;
  lastError?: string;
  createdAt: number;
  updatedAt: number;
}
```

> 注：设计稿中的 `done` 状态未使用——成功后直接从 DB 删除，不保留 done 记录。

- IndexedDB database：`textdb`（version 1）
- Object store：`write-queue`，keyPath: `id`
- `MAX_RETRIES = 3`（导出常量，QueueStatus 组件复用）

### 队列处理器 `src/lib/writeQueue.ts`

基于 `idb` 库封装。核心逻辑：

1. **入队** `enqueue(input, opts?)` — `async`，生成 id，status=pending，`await db.add()` 写入 IndexedDB，失败则 `fallbackEnqueue` 降级为直接调用 API；触发处理
2. **处理** `processQueue()` — 串行取出 pending 项（一次一个，避免 KV 并发写冲突）
3. **发送** — 调用现有 `writeData` / `deleteData` / `uploadFile`
4. **成功** — 从 DB 删除，触发 onSuccess 回调（toast + recordKey + stats 刷新 + history 刷新）
5. **失败** — retryCount++，指数退避（1s → 2s → 4s），最多 3 次；超过则 status=error，触发 onError
6. **恢复** — 页面加载时 `initQueue()` 扫描 pending/processing 项，重新入处理流程
7. **手动操作** — `retryItem(id)` / `discardItem(id)` / `retryAll()`
8. **网络恢复** — 监听 `online` 事件（`onlineListenerRegistered` 模块级标志防重复注册）
9. **订阅机制** — `subscribe(callback)` 返回取消函数，队列变化时通知 UI

### UI 组件 `src/components/QueueStatus.tsx`

- 右下角浮动指示器：
  - pending > 0：旋转图标 + 数字
  - error > 0：红色徽章 + 数字
  - 队列为空：隐藏
- 点击展开队列详情面板：
  - 每项：key、type 图标、status、retryCount（`{item.retryCount}/{MAX_RETRIES}`）、lastError
  - error 项："重试" / "丢弃" 按钮
  - 底部"全部重试"按钮

### 集成点

| 文件 | 改动 |
|---|---|
| `src/lib/writeQueue.ts` | **新增** — IndexedDB + 队列处理器 |
| `src/components/QueueStatus.tsx` | **新增** — 队列状态指示器 |
| `src/components/WriteCard.tsx` | handleWrite/handleDelete → `enqueue`；新增 `isSubmitting` 状态防重复点击；onSuccess 清除密码；onError 重置状态 |
| `src/components/FolderUpload.tsx` | 批量上传 → 逐个 `enqueue`；`checkDone()` 在全部回调完成后才 `setUploading(false)` |
| `src/App.tsx` | 挂载时 `initQueue()`，全局回调处理 toast + recordKey + stats + history 刷新；渲染 QueueStatus |
| `package.json` | 新增 `idb` 依赖 |

### 关键决策

- **透明替换**：用户点击"写入"后立即看到"已加入队列"，不阻塞 UI；成功/失败通过 toast 通知
- **与功能 2 联动**：队列处理成功后才 `recordKey`，避免记录从未成功的 key
- **密码存储**：队列项含 password 明文，存本地 IndexedDB。风险等同于前端 state，v1.3.0 接受；后续 E2EE 时一并处理
- **串行处理**：同一 key 的多次写入按顺序执行，避免竞态
- **enqueue async 化**：`await db.add()` 确保持久化成功后再通知订阅者和触发处理；IndexedDB 写入失败（如配额超限）时降级为直接调用 API

### 边界情况

- IndexedDB 不可用 → `fallbackEnqueue` 降级为直接 fetch（现有行为），不显示队列指示器
- 页面关闭时 pending 项保留，下次打开自动重试
- 网络恢复时自动触发处理（`online` 事件，只注册一次）

## 功能 4：Markdown 增强

### 现有基础

`src/components/MdRenderer.tsx` 已用 `react-markdown@10` + `remark-gfm@4`，是独立路由 `/md/{key}`。

### 插件方案

| 插件 | 功能 | 加载方式 |
|---|---|---|
| `rehype-highlight` + `highlight.js` | 代码语法高亮（atom-one-dark） | 主 bundle |
| `rehype-slug` | 标题 id 锚点 | 主 bundle |
| `rehype-autolink-headings` | 标题可点击链接 | 主 bundle |
| `remark-math` + `rehype-katex` | LaTeX 公式 | 主 bundle（KaTeX CSS 导入） |
| `mermaid`（动态 import） | Mermaid 图表 | 动态 import（未使用 remark-mermaid 插件） |

### 实际实现偏差（vs 设计稿）

1. **Mermaid 未使用 remark-mermaid 插件**：改为自定义 `MermaidBlock` 组件，检测 ` ```mermaid ` 代码块，动态 `import("mermaid")`，`mermaid.render()` 生成 SVG，`useState` 存 svg + `dangerouslySetInnerHTML` 注入。原因：remark-mermaid 插件与 react-markdown@10 兼容性不佳，自定义方案更可控。
2. **Mermaid securityLevel**：`mermaid.initialize({ securityLevel: "strict" })`，防止 XSS。
3. **KaTeX 未做动态加载**：remark-math + rehype-katex 直接加入主插件列表。原因：检测数学公式后动态切换 plugins 会导致 react-markdown 重新渲染闪烁，且 KaTeX 体积可接受。
4. **TOC 用 MutationObserver**：渲染后从 DOM 提取 h1-h4，生成目录树，右侧悬浮。点击平滑滚动，窄屏隐藏。

### 目录（TOC）

- `rehype-slug` 给 h1-h6 加 id
- 右侧悬浮目录组件，`MutationObserver` 监听 `.md-content`  DOM 变化提取标题
- 点击跳转，窄屏（< 1024px）隐藏
- 无标题时不显示目录

### 代码高亮主题

- `highlight.js` 的 `atom-one-dark` 主题（暗色风格，与项目整体风格一致）
- 代码块样式在 index.css 中定制

### 集成点

| 文件 | 改动 |
|---|---|
| `src/components/MdRenderer.tsx` | 插件配置、MermaidBlock 组件、TOC 组件、动态加载逻辑 |
| `src/index.css` | highlight.js / KaTeX / TOC / Mermaid 样式 |
| `package.json` | 新增 rehype-highlight / rehype-slug / rehype-autolink-headings / remark-math / rehype-katex / mermaid / katex |

### 边界情况

- Mermaid 图表需要客户端渲染，SSR/无 JS 环境不显示（本项目是 SPA，可接受）
- Mermaid 渲染失败时显示错误信息（`useState` 存 error）
- 大 markdown 文件渲染可能卡顿，v1.3.0 不做虚拟滚动

## 跨功能考虑

### 实施顺序（按风险从低到高，已执行）

1. **Phase 1：OpenAPI 文档** — 纯新增，零风险 ✅
2. **Phase 2：本地 Key 浏览** — 纯前端增量，不影响写入逻辑 ✅
